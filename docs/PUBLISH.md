# 公開の手渡し手順

この手順のGitHub作成・push・公開切替は本人が行います。この候補を作成しただけでは、リポジトリやアプリは公開されません。

1. 最終検証済みarchiveのファイル名・容量・SHA256を受け取った検証結果と照合します。新しい空フォルダへ、そのarchiveだけを展開してください。作業ディレクトリ全体や以前のリポジトリをコピーしないでください。生成済みbuild、ローカル設定、実メール、CSV、台帳、認証情報、過去のGit履歴は公開対象外です。
2. 展開したフォルダで `bash tools/test-all.sh` を実行し、合成デモと検証が成功することを確認します。Node.js 18以上・Python 3.9以上が必要です。Googleへの接続や本番書込みは行いません。LICENSEのMIT著作権表示は本人確認済みの `hirame6548` です。判明している第三者の権利条件があれば別途解決してください。表示名の承認はコード全行の過去由来の保証ではありません。
3. GitHubで**新しい空のprivateリポジトリ**を作成します。名前は例えば `kakeibo` です。README、LICENSE、gitignoreの自動生成は選ばず、空のままにします。既存の非公開リポジトリ の可視性・履歴・remoteは変更しません。
4. 展開フォルダ内に `.git` が無いことを確認し、本人が新規のGit履歴を作ります。Git作者名とメールアドレスを**最初のcommit前に**確認してください。個人メールを公開したくない場合は、GitHubのメール設定で本人用として確認したnoreplyアドレスを使います。アドレスを推測しないでください。新規privateリポジトリのURL・owner・名前を確認してから、そのリポジトリだけへファイルをcommit/pushします。
5. GitHub上で全ファイル、全commit、作者メールを確認します。収録は `tools/release-files.json` に挙がるファイルと `PUBLIC-MANIFEST.json` のみです。合成試験で後から生成した `webapp/build/` や個人ファイルは含めません。commit前の全差分も確認してください。秘密情報や個人メールが入っていた場合は公開せず、新しい安全な履歴を用意してから再確認します。
6. コードだけのdeveloper previewであることとREADMEの制約を確認したうえで、本人が**新規リポジトリだけ**をpublicへ切り替えます。既存privateリポジトリを公開してはいけません。公開URLを共有する前に、意図したファイルとライセンスが見えることを確認します。

一般Gmail/Driveコネクター、OAuth、新規GAS/Sheets配備、定期実行、実ブラウザー・mobileの動作は未実証です。cloneだけで家計簿が動くとは案内しません。実データを扱う前に、利用者の隔離した合成環境で権限とadapterを検証してください。本公開手順は本番への接続・アプリ配備を含みません。
